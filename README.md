# 義勇消防組織業務自主評核系統

依《115 年度義勇消防組織業務評核表(救災、救護義消)》建立。各分隊隨時上傳佐證資料、登錄自評缺失,大隊與業務科複評後自動計分並彙整成績。

## 啟動

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/streamlit run app.py
```

第一次啟動會建立資料庫,並產生 `data/initial_accounts.csv`(業務科、4 個大隊與 24 個分隊的帳號與初始密碼)。請把密碼交給各單位後刪除該檔案,此檔不會進入 git。

## 角色

| 角色 | 能做的事 |
|---|---|
| 分隊 | 上傳佐證檔案、登錄自評缺失、看自評試算;第一項只需填進退管理機制說明與佐證連結。複評完成後資料鎖定 |
| 大隊 | 登入後先看第九項「配合本局年度重大工作」(大隊評核:轄下各分隊成績加權 + 業務科配合事項);另可檢視轄下分隊的佐證與自評、登錄複評、看成績、匯出 Excel |
| 業務科 | 全部分隊的複評、業務科配合事項登錄、帳號管理 |

## 計分方式

- 各項配分與扣分、加分規則都在 `data/rubric.json`,換評核表只需改這個檔案。
- 分隊總分 = 一到七項得分(配分扣掉缺失扣分,最低 0)+ 加分。第六項依全年度爭取經費金額對照門檻。
- 只有業務科或大隊把分隊標為「複評完成」,該分隊才計入正式成績與大隊平均。
- 大隊總分 = 已完成複評分隊的算術平均 × 70% + 業務科配合事項(三項,每項 = 無缺失件數 ÷ 總送件數 × 10)。

## 資料位置

- 資料庫:`data/assessment.db`
- 佐證檔案:`data/uploads/<分隊>/<項次>/`
- 部署到 Streamlit Community Cloud 時檔案系統不會保存,請改用有持久磁碟的主機,或之後把檔案改存 Google Drive。

## 尚未串接

- 協勤民力管理系統、義消專長資料庫(第一、二項的自動核對)與補捐助案件資料(大隊業務科配合事項)。目前這些都是人工登錄。
- 帳號驗證集中在 `utils/auth.py` 的 `verify()`,之後改用民力科核發的帳號時只需替換這裡。

## 串接 Google Drive(佐證檔案放進各分隊的評核項目資料夾)

現有資料夾結構:縣局根資料夾 / 大隊 / 115年度義勇消防組織評核資料(分隊) / 01_編組狀況 … 07_監督管理情形。
啟用後,分隊在網站上傳的檔案會直接放進對應項目的資料夾,網站也會顯示「開啟此項目的 Drive 資料夾」連結。
資料夾以名稱關鍵字比對(編組、協勤民力資訊、訓練、協勤情形、裝備器材、爭取經費、監督管理、重大工作),不需要維護 ID 對照表;找不到對應資料夾時會在分隊資料夾下自動建立。

啟用步驟:
1. 在 Google Cloud 建立專案並啟用 Drive API,建立服務帳戶與 JSON 金鑰。
2. 把縣局根資料夾以「編輯者」權限共用給服務帳戶的 email(client_email)。
3. 複製 `.streamlit/secrets.toml.example` 為 `.streamlit/secrets.toml`,填入根資料夾 ID 與金鑰內容。
4. 重新啟動網站。沒有設定時,系統自動改存本機 `data/uploads/`。

注意:存在 Drive 的檔案由 Drive 管理,網站不提供刪除,要刪除請到 Drive 操作。

## 與義消專長資料庫共用帳號

登入帳號密碼讀取雲端試算表「115年義消總隊、各分隊基本資料及專長列表」的「系統帳號備份」分頁,
本系統不另外儲存密碼。對方系統新增帳號、改密碼、停用,約 1 分鐘內同步。`admin` 對應為業務科管理員。

啟用步驟:
1. 把該試算表以「檢視者」共用給服務帳戶(與串接 Drive 用的同一個)。
2. 雜湊方式已實測為 PBKDF2-SHA256(26 萬次),內建為預設值;日後對方改了演算法才需要重跑 `tools/detect_hash.py`。
3. 在 `.streamlit/secrets.toml` 填入 `ACCOUNT_SHEET_ID`、`ACCOUNT_HASH_SCHEME`(範本見 `secrets.toml.example`)。

「所屬單位」與本系統分隊名稱的對照在 `data/unit_alias.json`。科技義消分隊、防災館分隊不評核(`excluded`),其帳號登入時會顯示「此單位不在本次評核範圍」。
知本分隊一個帳號對應知本救災與知本救護兩個分隊,兩邊資料各自獨立填報,登入後在頁面上方切換。

## 第一項「編組狀況」的自動資料

編制人數、現有人數、平均年齡直接讀專長資料庫試算表:編制人數取自「編制表」,現有人數與平均年齡由「總清冊」的單位、職稱、年紀計算,都不含職稱為「顧問」的人員。
只讀這幾個欄位,不讀姓名、身分證字號、地址。約每 10 分鐘更新一次(`utils/roster.py`)。
讀不到試算表時,業務科可在評核登錄手動輸入。進退管理機制由分隊填說明與資料夾連結,業務科給分(最高 3 分)。

年齡核對:編組人員(不含顧問)年齡須在 18~60 歲(含),範圍設定在 `data/rubric.json` 的 `item1.age_min`、`age_max`。
系統只列出不在範圍的人數與總清冊列號,不自動扣分;業務科確認例外(派任時未屆齡而任期中屆齡者)後,可按「以系統核對結果填入」再調整人數。

## 資料存放位置

| 資料 | 存放位置 |
|---|---|
| 分隊的說明文字、進退管理機制說明與連結、承辦人與主管 | SQLite 資料庫 `data/assessment.db`(執行網站的那台電腦上) |
| 業務科與大隊的複評登錄、扣分、評分、業務科配合事項 | 同上 |
| 佐證檔案 | 設定好 Google Drive 時,存進該分隊對應評核項目的 Drive 資料夾(資料庫只記連結);未設定時存本機 `data/uploads/` |
| 帳號與密碼 | 不存本系統,讀專長資料庫試算表的「系統帳號備份」 |
| 編制、現有人數、平均年齡 | 不存,每次從專長資料庫試算表即時讀取 |

注意:`data/assessment.db` 沒有自動備份,也不在 git 裡。若部署在會重置檔案系統的主機(例如 Streamlit Community Cloud),重新啟動後資料會消失。

## 資料備份到 Google 試算表(每個分隊一個分頁)

分隊的基本資料、評核登錄、說明、佐證檔案清單,每次有異動都會整頁覆蓋寫入備份試算表對應的分頁;
業務科配合事項備份在「業務科配合事項」分頁。這份試算表是備份用,**不要手動編輯**——下次系統寫入會整頁蓋掉人工修改。

網站啟動時,若某分隊在本機資料庫完全是空白狀態(例如主機重啟清空了檔案),會自動從備份還原;
本機已有資料的分隊不會被備份覆蓋,避免用舊備份蓋掉新資料。還原每次執行只做一次(直到網站程序重啟)。

啟用步驟:
1. 建立一份新的 Google 試算表,依分隊各建一個分頁(分頁名稱=分隊名稱),可用下方指令一次建立。
2. 把試算表共用給服務帳戶(與串接 Drive、帳號表用的同一個),權限選「編輯者」。
3. 在 `.streamlit/secrets.toml` 填入 `BACKUP_SHEET_ID`。

目前使用的備份試算表:[義消評核系統-資料備份](https://docs.google.com/spreadsheets/d/1C-HBdI2kg9SKemyaK1J8VbEVT9Ua2F6yI2AgjTfzwic/edit)

## 登入失敗不鎖定

依使用者要求,連續輸入錯誤密碼不會鎖定帳號(`utils/auth.py` 的 `LOCKOUT_ENABLED = False`)。
失敗次數仍會記在本機 `login_fail` 表,只是不會拿來擋登入。要恢復鎖定,把該常數改回 `True` 即可(預設 5 次失敗鎖 10 分鐘)。

## 第三項「訓練情形」

依評核表拆成「(一)專業訓練(10 分)」「(二)常年訓練(10 分)」各自獨立計分,互不挪用(例如專業訓練扣超過 10 分,不會吃掉常年訓練的分數)。
分隊上傳訓練計畫、統計總表、課程表、相片、簽到表;業務科依佐證資料登錄缺失(專業訓練資料缺失、常年訓練時數不足、佐證資料缺失)。

## 第三項分隊填報介面

- **(一)專業訓練**:分隊選擇訓練類別(火災搶救類、緊急救護類、車禍救助類、水域救生類、山域搜救類、其他)與時數,可多筆。
  系統自動加總並顯示「專業訓練完成{火搶/緊急救護}訓練 ○ 小時,其餘訓練 ○ 小時」,救護義消分隊(名稱含「救護」)自動改列緊急救護類為必修項目。
- **(二)常年訓練**:分隊直接勾選 1~12 月中已完成訓練的月份,顯示「已完成本年度 ○ 個月份的常年訓練」。
- 這兩塊是分隊自行填報的統計資料,業務科複評時看得到(唯讀),但系統不會依此自動扣分——正式扣分仍由業務科依佐證資料登錄(C1/C2/C3)。

## 第四項分隊填報介面

依分隊類型(名稱含「救護」為救護義消,其餘為救災義消)顯示對應的協勤規定文字。
分隊勾選「本分隊本年度○○義消協勤佐證資料均已完整檢附」做自我宣告,可填補充說明;業務科複評時看得到這個宣告狀態,
覆核後依佐證資料登錄正式扣分(D1 未檢附扣 2 分、D2 每處缺失扣 0.5 分)。第 3 點(協勤民力系統登錄)由業務科抽檢給分,
沒有獨立的分隊勾選項,查有缺失時併入 D2 登錄。

## 第四項計分方式(勾選直接生效)

分隊勾選「資料已完整檢附」後立即生效,系統不扣「未檢附」的 2 分;未勾選則系統自動扣這 2 分,不需要業務科手動登錄或確認。
業務科只需核對佐證資料,確認有沒有個別缺失(每處扣 0.5 分),有的話在複評畫面登錄即可。
臺東救護義消分隊、知本救護義消分隊依名稱含「救護」自動判定為救護義消,其餘分隊為救災義消。

## 第五項「裝備器材維護情形」

拆成「1、裝備器材造冊管理(5分)」「2、個人裝備年度檢查紀錄(5分)」各自獨立計分,互不挪用。
分隊各自勾選是否已完成,勾選後**直接生效**(跟第四項同一套做法):勾了不扣那 5 分,沒勾系統自動扣完那 5 分,
不需要業務科再確認「是否已完成」本身。業務科核對佐證資料是否翔實,如發現個別缺失(即使已勾選),
仍可登錄「每處缺失扣 0.5 分」(E2、E4)。

## 第六、七、八項

- **第六項(全年度爭取經費,2 分)**:分隊逐筆填寫案件說明與金額(議員設備補助、外界捐贈等),可新增多筆;
  業務科逐筆勾選「確認計入」,只有已確認的金額加總後依門檻換算分數(30 萬以上 2 分、20 萬以上 1.5 分、10 萬以上 1 分、3 萬以上 0.5 分)。
- **第七項(監督管理/財務管理,3 分)**:分隊勾選「公佈資料齊全」直接生效(跟第四、五項同一套做法):勾了得 3 分,
  沒勾系統自動扣完 3 分。業務科核對後如仍發現個別缺失,可登錄每處扣 0.5 分(G1)。
- **第八項(分隊平均分數加分,無固定配分)**:
  - 1、複訓到訓比例加分(最高 2 分):只有業務科能登錄,分隊不開放填寫。
  - 2、救護技能競賽(加 1 分):分隊填寫參賽項目後直接生效加 1 分,業務科審核後可勾選「取消」。
  - 3、建設性作為(每案加 2 分):分隊可新增多筆說明,業務科逐筆勾選「可分享」才給分,未確認的案件分隊可自行刪除。

## 佐證資料改為直接在 Drive 操作(不經過本系統上傳)

Google 服務帳戶沒有自己的儲存空間配額,無法在個人 Google 帳號(非企業版「共用雲端硬碟」)底下建立有內容的檔案,
上傳一定會失敗(`Service Accounts do not have storage quota`)。這個限制無法繞過,所以系統不再處理檔案上傳:

- 每個評核項次只顯示該分隊對應的 Drive 資料夾連結,請直接在 Drive 裡上傳、整理、刪除檔案。
- 可展開「查看資料夾內目前有哪些檔案」,唯讀列出資料夾內容(60 秒快取,避免每次畫面重整都呼叫 Drive API)。
- 這樣也避免多人同時上傳造成系統負擔的疑慮,上傳行為完全交給 Drive 自己處理。
- 舊版上傳機制留下的 `evidence` 資料表與相關函式保留在 `utils/db.py`(不再使用,不影響運作),之後要徹底清除可以再移除。
